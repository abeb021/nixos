# NixOS config tutorial

This repo follows the same shape as [Frost-Phoenix/nixos-config](https://github.com/Frost-Phoenix/nixos-config): one flake, one directory per machine, shared system modules, and Home Manager modules. The programs, theme, and host details are yours. The reference rice (Hyprland binds, waybar, rofi, their packages) is not copied.

Rebuild after any change:

```bash
sudo nixos-rebuild switch --flake ~/nixos#nixos
```

The zsh alias for that is `nrs`.

## How a rebuild finds your config

NixOS does not read `/etc/nixos/configuration.nix` for this setup. It evaluates the flake:

```text
flake.nix
  nixosConfigurations.nixos
    modules = [ ./hosts/nixos ]
      hosts/nixos/default.nix
        hardware-configuration.nix   # disks, cpu, generated
        modules/core                 # shared system
          modules/core/user.nix
            home-manager.users.abeb-nix
              modules/home           # your dotfiles
```

`#nixos` is the attribute name in `flake.nix`, and it is also the hostname. Both come from `host = "nixos"` in `specialArgs`.

## Directory map

```text
flake.nix                 inputs and nixosConfigurations
flake.lock                pinned revisions of those inputs
hosts/nixos/              this machine only
modules/core/             NixOS modules shared by every host
modules/home/             Home Manager modules for the user
pkgs/                     packages built in this repo, exposed via an overlay
scripts/scripts.nix       turns every scripts/scripts/*.sh into a command
scripts/scripts/          those shell scripts
TUTORIAL.md               this file
```

| Path | Owns |
| --- | --- |

| `hosts/nixos/default.nix` | Intel GPU firmware, media drivers, upower. |
| `modules/core/bootloader.nix` | systemd-boot. |

| `modules/core/system.nix` | Flakes, timezone, locales, keyboard, `stateVersion`. |
| `modules/core/hardware.nix` | Graphics and redistributable firmware. |
| `modules/core/bluetooth.nix` | Bluetooth. |
| `modules/core/pipewire.nix` | Audio. |
| `modules/core/security.nix` | rtkit, GNOME keyring, PAM. |
| `modules/core/wayland.nix` | SDDM, Hyprland, niri, portals, session variables. |
| `modules/core/program.nix` | System programs and `environment.systemPackages`. |

## Flake inputs

`flake.nix` declares where packages come from:

- `nixpkgs` is `nixos-unstable`.
- `home-manager` follows that same nixpkgs, so system and user packages do not drift apart.
- `zen-browser` is a third flake. `modules/home/zen.nix` imports `inputs.zen-browser.homeModules.beta`.

`inputs.nixpkgs.follows = "nixpkgs"` means “use my nixpkgs, do not fetch a second one.”

`specialArgs` is how non-package values reach modules. Every NixOS module in this config can take `inputs`, `username`, `host`, and `self`. Home Manager gets the same set through `extraSpecialArgs` in `modules/core/user.nix`.

```nix
specialArgs = {
  host = "nixos";
  inherit self inputs username;
};
```

`username` is `abeb-nix`. The account, the home directory, and `home-manager.users.abeb-nix` all use that variable. Change it in one place in `flake.nix` if the name ever changes. The uid stays `1000` so it matches the existing home directory.

## System vs home

NixOS modules (`modules/core`) configure the machine: users, services, the kernel, system packages. They install files under `/etc`, `/run`, and the system profile.

Home Manager modules (`modules/home`) configure one user: `~/.config`, `~/.zshrc`, GTK, editor settings. They run as part of `nixos-rebuild` because `modules/core/user.nix` imports the Home Manager NixOS module. There is no separate `home-manager switch`.

`home.stateVersion` is `"26.05"`. `system.stateVersion` is `"26.11"`. Leave both alone. They record the NixOS release that first created the system, and changing them can rewrite existing state.

`backupFileExtension = "hm-bak"` tells Home Manager to rename a file it wants to own, instead of refusing to start, when that file already exists in the home directory.

## What stays out of the repo

Secrets and a few live trees are copied once by `scripts/scripts/copy-settings.sh` and are not committed:

- `~/.ssh`, `~/.gnupg`, `~/.git-credentials`, `~/.config/gh`
- `~/.p10k.zsh` (the prompt theme; Home Manager only sources it)
- Kitty, nvim, Tanjun, and Hyprland wallpaper assets

Tanjun stays a git checkout under `~/Programming/Tanjun-shell`. Home Manager (`modules/home/tanjun.nix`) owns the symlinks and the small Hyprland `hyprland.lua` stub; the rice and QML tree stay in that repo.

Run the copy only when you still have the Arch disk:

```bash
sudo bash ~/nixos/scripts/scripts/copy-settings.sh
```

After a rebuild the same script is also on `PATH` as `copy-settings`.

## Add a system package

Put it in `environment.systemPackages` in `modules/core/program.nix` if every host should have it. Put it in `hosts/<name>/default.nix` if only one machine needs it (firmware, GPU drivers, laptop power).

Prefer a NixOS program module when one exists. Zoom is `programs.zoom-us.enable`, not `pkgs.zoom-us`, because the module wraps the portal. Firefox, Neovim, and Wireshark are the same idea.

Then `nrs`.

## Add a Home Manager module

1. Create `modules/home/something.nix`.
2. Add `./something.nix` to the `imports` list in `modules/home/default.nix`.

A directory works the same way as a file when it contains `default.nix`. `./zsh` loads `modules/home/zsh/default.nix`, which loads `zsh.nix` and `zsh_alias.nix`.

User packages that should not be system-wide go in a home module:

```nix
{ pkgs, ... }:
{
  home.packages = with pkgs; [ ripgrep ];
}
```

`useUserPackages = true` and `useGlobalPkgs = true` mean those packages use the same nixpkgs as the system and are installed into the user profile.

## Add a shell alias

Edit `modules/home/zsh/zsh_alias.nix`. The prompt, history, and keybindings stay in `zsh.nix`.

| Alias | Command |
| --- | --- |
| `nrs` | rebuild and switch |
| `nrb` | rebuild and set it as the next boot, do not switch now |
| `nrt` | test the build, do not touch the bootloader |
| `nrd` | show what would change, do not build |
| `nfu` | update `flake.lock` |
| `nup` | update the lock and switch |
| `ngc` | delete old generations |
| `gens` | list system generations |

## Add a command from a script

1. Add `scripts/scripts/name.sh`. The first line must be a shebang.
2. Rebuild.

`scripts/scripts.nix` reads that directory and installs each `*.sh` file as a package whose name is the file name without `.sh`. `copy-settings.sh` becomes the `copy-settings` command. Home Manager puts those packages on your `PATH` because `modules/home/default.nix` imports `scripts/scripts.nix`.

## Add a custom package

1. Write a derivation, as `pkgs/simplicity-sddm-theme.nix` already does.
2. Add an attribute in `pkgs/default.nix`:

```nix
{ pkgs, ... }:
{
  simplicity-sddm-theme = pkgs.callPackage ./simplicity-sddm-theme.nix { };
}
```

`modules/core/nixpkgs.nix` turns that file into an overlay, so the rest of the config sees `pkgs.simplicity-sddm-theme`. `modules/core/wayland.nix` installs it for SDDM. Do not `callPackage` the theme again from a module; the overlay is the one definition.

## Add another machine

1. Copy `hosts/nixos` to `hosts/laptop` (or whatever the hostname should be).
2. Replace `hardware-configuration.nix` with the output of `nixos-generate-config` from that machine.
3. Keep the import of `../../modules/core`. Put only the differences in `hosts/laptop/default.nix` (GPU, battery, bootloader overrides).
4. Add an attribute next to `nixos` in `flake.nix`:

```nix
laptop = nixpkgs.lib.nixosSystem {
  inherit system;
  modules = [ ./hosts/laptop ];
  specialArgs = {
    host = "laptop";
    inherit self inputs username;
  };
};
```

`networking.hostName` reads `host`, so the attribute name and the hostname stay the same. Build it with:

```bash
sudo nixos-rebuild switch --flake ~/nixos#laptop
```

A VM host in the reference config turns systemd-boot off and enables GRUB, because QEMU’s default firmware is not UEFI. Do that in the VM’s `default.nix` with `lib.mkForce`, not by editing `modules/core/bootloader.nix`.

## Keyboard, locale, audio, desktop

- Keyboard layout `us,ru`, Caps Lock as Escape, and Win+Space to switch layouts: `modules/core/system.nix`.
- PipeWire (Pulse, ALSA, JACK): `modules/core/pipewire.nix`. `security.rtkit` is required for the low-latency path.
- SDDM theme `simplicity`, Hyprland as the default session, niri also enabled, portals, cursors: `modules/core/wayland.nix`.
- GTK and the dark preference: `modules/home/gtk.nix`. Do not copy those files from Arch; Home Manager owns them.

## Editors

`modules/home/editors.nix` enables VS Code and Cursor. Settings JSON lives in `modules/home/files/`. Extension lists live in `modules/home/extensions.nix`. `mutableExtensionsDir = false` means the editor must not install extensions on its own; add them in Nix and rebuild.

## Check a change before switching

```bash
nixos-rebuild dry-activate --flake ~/nixos#nixos
sudo nixos-rebuild test --flake ~/nixos#nixos
```

`test` activates the config but leaves the bootloader on the previous generation, so a reboot returns to the last `switch` or `boot`. If a switch boots to a bad generation, pick the previous one in the systemd-boot menu, then fix the config.

`nix flake update` moves `flake.lock`. Review that diff before `nup`; it can change every package.
